# github

## What it does

One GitHub sign-in. Agents read and write GitHub as you, labelled as AidenHQ: issues, pull requests, reviews, checks,
Projects boards and code. The code host runs on the same account: clones, push, PR, merge at the reviewed head once
green, `create_repo`, land, and the git rules that tier each write. Every write is an AidenHQ write record decided by
its gate; nothing an agent does on GitHub counts as your approval.

Everything agents write says so: commits carry `Co-authored-by: AidenHQ <agent name> <noreply@aidenhq.ai>`, posted text
ends with `🤖 Generated by <agent name> with [AidenHQ](https://aidenhq.ai)`. The token stays inside the `github`
service; other modules get typed code host operations through the kernel (`POST /v1/codehost/:op`).

## Connect

Board, Settings, GitHub (`#/setup/github`), about a minute. Press Connect GitHub, open github.com/login/device and type
the code, then allow AidenHQ. It asks for `repo`, `read:org`, `workflow` and `project`, plus `admin:org` while the `ci`
module is on. An organization that restricts OAuth apps needs an owner to approve AidenHQ; one with SAML SSO needs you
to authorize the sign-in for it. The GitHub card on Connections names either case with its link.

Optional: set `github_fleet_org` (the card's **Fleet repos**, Change) to an org you can create repositories in, and
agent-built repos live there; unset, they live on this server (`codehost-local`).

## What agents get

Two connections. Destructive tools are reviewed and need a grant naming them.

- `github` (AidenHQ's own): reads such as `github_issue_read`, `github_search_issues`, `github_pr_files`,
  `github_pr_threads`, `github_job_log`, `github_project_read`; destructive issue and PR writes
  (`github_issue_comment`, `github_pr_review` (comment only), `github_rerun_failed`, `github_product_issue*`).
- `github_official` (GitHub's own MCP server, as you): read-only, such as `get_file_contents`, `get_commit`,
  `list_commits`. Every mutating tool is refused.
- Warehouse source `src_github` (issues, project items, changes).
- Settings include `upstream` (off, issues), `release_window_minutes` (60), `maintainer_repos`, `github_fleet_org` and `github_orgs`.

## New installs

In the default bundle. Until you connect, a banner says the agents can't use GitHub, and the fleet's repos stay on this
server (`codehost-local`).

# Slack triage

`slack_owner` once gives the owner's Slack ID, `<me>`; null: finish "Slack not connected". `routine_events` with the batch id from the task (`New events: batch …`); `pending`: call again after `retry_after_s`; none: finish; `expired`: finish saying the batch's events were gone before this run. Each event has `id`, `resource` (the channel), `kind`, `author` (a Slack user ID), `text`, `url` (the permalink) and, on a reply, `thread` (its thread's root ts). A message's `id` is `<channel>:<ts>`.

Decide each event on its own text the moment you see it, however recent. Default is nothing. An event marked `truncated` carries only its first 2000 characters: read the whole message (`slack_read_thread` with its thread, or its own ts) before you decide it.

- **Task**, one label: `needs-response`, a direct ask for `<me>`'s own decision, answer, review, approval or access (@mention, DM, or reply to their message; a thread reply is for whoever started it or is @mentioned, so "I need your call" in someone else's thread is for them); `todo`, `<me>` (author) promises something concrete; `waiting-on`, someone explicitly promises `<me>` something concrete, titled by what is owed and by whom.
- **Pinned:** `reaction_added` (the owner's task emoji on a message; `url` is that message, its ts is the `id`'s second part) is a task whoever wrote it. `slack_read_thread` the message; marker `source:slack:pin:<channel>:<ts>`, `dedupe_closed: true`, label `todo`, a title of what the owner needs to do ("Read: <topic>" if informational), Reason starting "Reacted :pushpin: in Slack.", `Type: Slack (pinned)`, and for a thread reply `related_markers: ["source:slack:<channel>:<thread root>"]`. When that dedupes onto an existing open thread task, `task_comment` "Pinned in Slack: <url>" on it (the record that it tracks this pin).
- **Answered or unpinned:** a message from `<me>` in a thread, or a `reaction_removed` or repeat `reaction_added`, may update a task. `task_search` the pin marker (`source:slack:pin:<channel>:<ts>`) and the message's thread marker (`source:slack:<channel>:<thread or ts>`); a removal or re-pin comment goes only on a task with the pin marker or a "Pinned in Slack: <url>" comment for this message; for an open task read the thread and `task_comments`, then add one `task_comment` when the state changed: "Answered in Slack: <url> — left open for the owner to close." when `<me>`'s reply answers the ask, "Reaction removed in Slack: <url> — left open for the owner to close.", or "Pinned again in Slack: <url> — left open for the owner." after a removal line for this message (<url>). A concrete promise by `<me>` is also a `todo`. Tasks are the owner's: never finish one.
- **Alert:** production down, a security incident, or a direct ask from `<me>`'s manager or a company executive needing an answer now. Unsure: a `needs-response` task.

Task: `marker: source:slack:<channel>:<thread or ts>` (a reply's `thread` is its root, and `slack_read_thread` with it shows the thread; `deduplicated: true` means done, `task_comment` only genuinely new information), `title` `Reply to <person>: <topic>` or the action or owed item and owner, `priority` `medium` (`high` only for a deadline today or tomorrow or a blocker; `low` for nice-to-haves), `description` your mission's format plus `PR: https://github.com/<owner>/<repo>/pull/<n>` under Source when the ask is to review, approve or merge that one PR (the task closes with it). Use names, not ids (`slack_read_user_profile`, `slack_search_channels`; on failure "someone in #channel" or "a DM").

Alert: `notify` `kind: "alert"`, one-line `text` (what, who, what is needed) ending with the event's `url`, `dedupe_key: "slack:<channel>:<thread or ts>"`; one alert per thread an hour across all agents, one per incident thread per run. `reason: "duplicate"`: call again with the key ending `:worse` and a text saying what changed only if the thread got worse (spread, second incident, customer impact). `reason: "error"`: a `needs-response` task instead.

`task_finish` with a count line, e.g. "12 events: 8 ignored, 2 tasks (1 needs-response, 1 waiting-on), 1 pinned, 1 marked answered, 1 urgent".

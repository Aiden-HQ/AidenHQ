# App starter

What every new app's repo starts from: **Vite + React + TypeScript, Tailwind CSS 4 and shadcn/ui** (Radix primitives,
lucide icons), served by a small Node server with no runtime dependencies. It looks like a modern product out of the box
and already follows the design system's rules (the product's `modules/core/design-system/`): a sidebar shell with a
bottom bar on phones, a page header, a summary that counts what the filters show, filters that apply as they change
and live in the URL, a sortable table, details in a sheet that Back closes, toasts with Undo, and loading, error, empty,
no-match and unknown-value states, in light and dark and all four palettes.

Copy this folder into the new repo (without `node_modules` and `dist`), add the CI template
(`modules/core/templates/ci/`), then replace the sample data and the example page with the app's own.

```sh
npm ci
npm test          # builds, serves and checks the page, its CSP, the health check and the API
npm run build     # typecheck + production build into dist/
npm start         # serves dist/ and the API on PORT (8080)
npm run dev       # Vite with hot reload; run `npm start` alongside it for the API (proxied from /api)
```

## What's where

| Path | What |
|---|---|
| `server.mjs` | Serves `dist/`, `/api/health` (`{ok: true, checks: []}`) and the example API (`/api/items`), with the CSP and the identity check (`aidenhq-identity.mjs`, copied unchanged: `req.user` is the signed-in person or agent). Replace `ITEMS` with the app's store. |
| `src/App.tsx` | The shell: sidebar (desktop), bottom bar (phone), header with the theme menu, and the routes. |
| `src/pages/projects.tsx` | The example page (list, filters, summary, paged table, detail sheet, every state). Copy its patterns, not its data. |
| `src/components/blocks/` | The building blocks pages are composed from: `page` (Page, PageHeader, PageSection, PageSplit), `stat-strip`, `data-table` (SortHead, Pagination, `paginate`), `board` (Board: lanes by stage), `activity` (ActivityList), `states` (StatePanel, TableSkeleton), `detail-list`, `form` (Field, FormSection, FormActions) and `charts` (BarList, TrendChart, ScheduleChart; no chart library). |
| `src/pages/catalog.tsx` | `/catalog`: every block and component in use, themed, with palette and mode pickers. Keep the route while it helps reviews, but take the "Components" link out of the app's navigation (and out of mockups): people using the app never need it. |
| `AGENTS.md` | The short rules for anyone (people or agents) changing this app's UI. Keep it in the app's repo. |
| `src/components/ui/` | shadcn/ui components as source (generated by the shadcn CLI, then owned here). Add more with `npx shadcn@4.23.0 add <name>`, then fix what the CLI gets wrong here (below) and pin any new dependency exactly. |
| `src/styles/tokens.css`, `src/styles/shadcn.css` | The design system's theme, vendored unchanged. Never edit them here. |
| `src/hooks/use-url-state.ts` | Filter state in the URL (`set` replaces, `push` adds a history entry for details). |
| `src/lib/csp.ts`, `public/theme.js` | The CSP nonce for Radix's run-time styles, and light/dark/palette before first paint. |

## Rules that come with it

- **CSP:** `script-src 'self'` and `style-src 'self' 'nonce-…'`, nothing else. No inline `<script>`, no CDN, no
  `'unsafe-inline'`. A library that injects `<style>` tags must take the nonce (`cspNonce` from `@/lib/csp`); one that
  can't (Sonner, for example) is not used. Check the browser console for CSP violations after every new component.
- **Theme:** colours come from Tailwind's theme names (`bg-background`, `text-muted-foreground`, `bg-primary`, `text-link`,
  `bg-ok-soft`, `text-danger`…), never literal colours. Tailwind's `accent` is the subtle hover fill; the brand colour is
  `primary`. Dark mode is `dark:`, driven by `<html data-theme>`.
- **After `shadcn add`:** the CLI can't read the `@/` alias under TypeScript 7 (no `baseUrl`), so it writes
  `import { cn } from "cn"` and adds an unpinned `cn` package. Change the import to `from "@/lib/utils"`, run
  `npm uninstall cn`, and revert any change it made to `src/index.css` (the theme comes from `shadcn.css`; never add a
  `.dark` block or literal colours there). Then set any new dependency to an exact, 7-day-old version. A `<style>` tag
  the new component renders needs `nonce={cspNonce}`.
- **Dependencies:** pinned exactly, each published at least 7 days ago (`node .github/supply-chain/best-version.mjs npm
  <pkg>` from the CI template), installed with `npm install --save-exact --before=<7 days ago>` so transitive versions
  pass too, lockfile committed.
- **Review states:** `?preview=loading|error|empty` shows that state of the example page with the sample data, so
  `ui-review` can screenshot it. Remove it with the sample data, and give the real app a seed mode instead.
- A shared app also follows the product's `docs/setup.md`, "What a shared app must do" (the identity check is in place).

# App starter

What every new app's repo starts from: **Vite + React + TypeScript, Tailwind CSS 4 and shadcn/ui** (Radix primitives,
lucide icons), served by a small Node server with no runtime dependencies. It works like a modern product out of the box and
meets the design system's floors (the product's `modules/apps-platform/design-system/`): a sample top-bar shell, a page header, a summary that counts what the filters show, filters that apply as they change
and live in the URL, a sortable table, details in a sheet that Back closes, toasts with Undo, and loading, error, empty,
no-match and unknown-value states, in light and dark and every palette and preset. Everything beyond that page is a
library to import from: an app's build carries only what it imports (the e2e test checks the example's bundle).

Copy this folder into the new repo (without `node_modules`, `dist`, `catalog.html` and `src/catalog/`), add the CI template
(`modules/ci/template/`), then replace the sample data, the example page and the shell with what fits the app. The shell, the example and the
blocks are a starting point, not a required look.

```sh
bun install --frozen-lockfile --ignore-scripts
bun run lint     # Oxlint (well under a second): nav, header, colour and effect rules; each message says the fix
bun run test          # component tests (bun test), then builds, serves and checks the page, its CSP, the health check and the API
bun run screens   # Playwright: starts the seeded preview, screenshots every feature-map page at 1440, 1920, 2560, 768 and 390 in light and dark, runs e2e/ flows, stops it
bun run preview   # build, then serve dist/ and the API with the sample data on 4173 (what `screens` starts)
bun run build     # typecheck + production build into dist/
bun run start         # serves dist/ and the API on PORT (8080; compose.yaml publishes it on the host's loopback, see below)
bun run dev       # Vite with hot reload; run `bun run start` alongside it for the API (proxied from /api)
bun run catalog   # the starter's dev-only component catalog (catalog.html): every piece, variant, shell and preset
```

## Publishing the port

`compose.yaml` publishes the app on the host's loopback (`127.0.0.1:8080:8080`). On deploy the platform sets that host port to the app's `port:` in `apps.yaml` (pick a free one), so leave the line as it is. That port is what makes the app reachable: the board's Open link, the tailnet node and the checks all use it.

## What's where

| Path | What |
|---|---|
| `server.mjs` | Serves `dist/`, `/api/health` (`{ok: true, checks: []}`) and the example API (`/api/items`), with the CSP and the identity check (`aidenhq-identity.mjs`, copied unchanged: `req.user` is the signed-in person or agent). Replace `ITEMS` with the app's store. |
| `feature-map.json` | The app's pages and a few stateful URLs, each with what should be visible there, so a UI review sees the filtered view, the open detail sheet and the deep link, not just `/`. See "The feature map" below. |
| `src/App.tsx` | The example's shell (`TopBarShell`) and routes (`ROUTES`, picked by `useLocation().path`; each one is also in `server.mjs` `PAGES`, so a reload answers 200). Pick the shell that fits the app's navigation: `TopBarShell` (variants `plain`, `brand`), `SidebarShell` (`sidebar`, `floating`, `inset`), `BareShell` (`full`, `centered`), or your own. |
| `src/pages/projects.tsx` | The example page (list, filters, summary, paged table, detail sheet, every state). Copy its patterns, not its data. |
| `src/pages/teams.tsx` | A second route: a small table whose team links open the projects page filtered (`/?team=…`). |
| `src/components/blocks/` | Optional building blocks, one line each below. |
| `catalog.html`, `src/catalog/` | The dev-only catalog (`bun run catalog`): every block, component and variant, the shells and the theme presets side by side, with palette and mode pickers (`?palette=crisp&mode=dark`). Not an app route, never built; apps leave it out. |
| `AGENTS.md` | The app's map for anyone (people or agents) changing it: which file owns which screen and route, how to run, test and lint it, and the UI rules. Keep it in the app's repo and current. |
| `src/components/ui/` | shadcn/ui components as source (generated by the shadcn CLI, then owned here). Add more with `bunx shadcn@4.23.0 add <name>`, then fix what the CLI gets wrong here (below) and pin any new dependency exactly. |
| `src/styles/tokens.css`, `src/styles/shadcn.css` | The design system's theme, vendored unchanged. Never edit them here. |
| `src/styles/presets/` | Theme presets (palette light and dark, accent, radius, fonts, density), vendored unchanged: `crisp`, `polished`, `editorial`, `dense`, `ops`, `indigo`, `soft`, `slate`, `minimal`, `graphite`. Pick one by importing it after `shadcn.css` in `src/index.css` and setting `<html data-palette="<name>">` in `index.html`, or adapt it in a `theme.css`. A starting point, not a rule. |
| `THIRD_PARTY.md` | Where vendored component code comes from, and its licence. |
| `src/lib/navigation.tsx` | The app's navigation: `useLocation()` (path and query; re-renders on every change), `Link` (an `<a href>` that moves without a page load), `navigate(href)`, and `useUrlState()` for state in the query (`set` replaces, `push` adds a history entry for details). A link click, Back/Forward and a reload all render the page the URL names. |
| `src/lib/notify-owner.ts` | `notifyOwner()`: call it after the server stored people's feedback or a request, and the app's feedback agent (registry `feedback_to`) wakes within a minute to read it through the app's agent API (shared apps; no text travels). |
| `src/lib/csp.ts`, `public/theme.js` | The CSP nonce for Radix's run-time styles, and light/dark/palette before first paint. |

## The feature map

`feature-map.json` sits next to `server.mjs` and lists the app's pages plus a few stateful URLs, with a note on what
should be visible at each: the filtered view, the open detail sheet, the empty state, a deep link. `ui-review` runs from
the app's folder and reviews these paths by default, so the states where dead clicks and broken pages hide are covered
without anyone naming them. An explicit `--paths` still wins.

```json
{
  "pages": [
    { "path": "/", "shows": "Projects: the summary counts, the filter bar and the first page of the table" },
    { "path": "/?status=late", "shows": "Projects filtered to Late: only late rows and a Clear filters button" },
    { "path": "/?item=search-v2", "shows": "The Search v2 detail sheet open over the list; Back closes it" }
  ]
}
```

- One entry per page (a `path` starting `/`), then two to four stateful URLs that matter for that page; `shows` says
  what a reviewer should see there, and it is printed as the heading of that path in the review report.
- Every path's pathname belongs in `server.mjs` `PAGES`, so a reload of it answers 200 rather than the 404 page.
- Sample ids and filter values are fine (`?item=search-v2`); use ones the sample data always has, and replace them
  with the app's own seed data.
- No map is not a failure: an app without one is crawled from `/` (its same-origin links, two deep). A map that exists but isn't valid JSON, or
  has no `pages` with a `path` on the app itself (a `/…` path; `//host/…` is refused), stops `ui-review` with an error so
  it gets fixed.

## The library

Everything is optional; import what the page needs. Variants are props.

**Blocks** (`src/components/blocks/`):
- `top-bar-shell` TopBarShell (`plain`, `brand`), `sidebar-shell` SidebarShell (`sidebar`, `floating`, `inset`; phone bottom bar), `bare-shell` BareShell (`full`, `centered`).
- `page`: Page (`wide`, `narrow`), PageHeader, PageSection, PageSplit (main column and side rail).
- `stat-strip` StatStrip (`divided`, `plain`, `tinted`; tones; `trend` sparkline per figure); `kpi` KpiCard (delta against a period, trend, Card variant); `sparkline` Sparkline.
- `data-table`: SortHead, Pagination, `paginate`; `table-toolbar`: ColumnToggle, SelectionBar (bulk actions).
- `board` Board (lanes by stage); `activity` ActivityList; `timeline` Timeline (`dots`, `icons`); `tracker` Tracker (status per period, e.g. uptime).
- `states`: StatePanel, TableSkeleton; `detail-list` DetailList.
- `form`: Field, FormSection, FormActions; `settings`: SettingsGroup, SettingsRow; `stepper` Stepper (`numbered`, `bar`).
- `combobox` Combobox (one or `multiple`); `date-picker` DatePicker, DateRangePicker (with presets); `command-palette` CommandPalette (⌘K).
- `charts`: BarList, TrendChart, ScheduleChart (no chart library).

**Components** (`src/components/ui/`, shadcn/ui): accordion, alert, alert-dialog, avatar, badge (`default`, `soft`,
`outline`, `secondary`, `dot`…), breadcrumb, button (`default`, `soft`, `outline`, `secondary`, `ghost`, `link`,
`destructive`), button-group, calendar, card (`default`, `flat`, `bordered`, `elevated`), checkbox, collapsible, command,
dialog, dropdown-menu, empty, hover-card, input, input-group, kbd, label, popover, progress, radio-group, scroll-area,
select, separator, sheet (`side`; `size` `sm`…`xl`), sidebar, skeleton, slider, spinner, switch, table (`default`,
`compact`, `striped`), tabs (TabsList `default`, `line`, `boxed`), textarea, toast and toaster, toggle, toggle-group,
tooltip.

**Opt-in, not installed:** recharts-based charts (shadcn's `chart`) when the hand-rolled charts aren't enough:
`bunx shadcn@4.23.0 add chart` and `bun add recharts@3.10.1` (published 2026-07-25); its `ChartStyle`
renders a `<style>` tag, so give it `nonce={cspNonce}`. Drag and drop (`@dnd-kit`), motion libraries and other kits
stay out unless an app needs them (guidelines: the stack).

## Rules that come with it

- **CSP:** `script-src 'self'` and `style-src 'self' 'nonce-…'`, nothing else. No inline `<script>`, no CDN, no
  `'unsafe-inline'`. A library that injects `<style>` tags must take the nonce (`cspNonce` from `@/lib/csp`); one that
  can't (Sonner, for example) is not used. Check the browser console for CSP violations after every new component.
- **Theme:** colours come from Tailwind's theme names (`bg-background`, `text-muted-foreground`, `bg-primary`, `text-link`,
  `bg-ok-soft`, `text-danger`…), never literal colours. Tailwind's `accent` is the subtle hover fill; the brand colour is
  `primary`. Dark mode is `dark:`, driven by `<html data-theme>`.
- **After `shadcn add`:** the CLI can't read the `@/` alias under TypeScript 7 (no `baseUrl`), so it writes
  `import { cn } from "cn"` and adds an unpinned `cn` package. Change the import to `from "@/lib/utils"`, run
  `bun remove cn`, and revert any change it made to `src/index.css` (the theme comes from `shadcn.css`; never add a
  `.dark` block or literal colours there). Then set any new dependency to an exact, 7-day-old version. A `<style>` tag
  the new component renders needs `nonce={cspNonce}`.
- **Dependencies:** pinned exactly, each published at least 7 days ago (`node .github/supply-chain/best-version.ts npm
  <pkg>` from the CI template), installed with `bun add` so transitive versions
  pass too, lockfile committed.
- **Review states:** `?preview=loading|error|empty` shows that state of the example page with the sample data, and
  `?seed=worst` serves the worst-case rows (long diacritic name, very long email, one-letter name, a missing owner, counts
  of 1 and 1,284), so
  `ui-review` can screenshot it. Remove it with the sample data, and give the real app a seed mode instead: `bun run
  preview` serves the app with fixture data (an in-memory store, no database) on port 4173, and `playwright.config.ts`
  starts it for `bun run screens`.
- A shared app also follows the product's `docs/design/access.md`, "What a shared app must do" (the identity check is in place).

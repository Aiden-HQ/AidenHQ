# Ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new optional `ship` module owns every PR's lifecycle (fleet-authored and handed-over), taking each to merge inside
the repo's rules, with every knob a per-repo setting.

**Architecture:** `ship` (new module, service plus skill) holds settings, adoption records, the round loop, the report and the
metrics, and absorbs `modules/github/service/src/pr-watch.ts`. `github` keeps typed effects (push with lease, update-branch,
approve, enqueue, merge, comment) plus `merges.ts`/`merge-gate.ts` as the merge primitive; `decide` gains action results.
Engineers do the judgment work in one task per PR.

**Tech Stack:** TypeScript on Node 24 (`.ts` run directly), node:test, GitHub REST/GraphQL through the code host.

**Spec:** `docs/superpowers/specs/2026-11-24-ship-design.md`

## Global Constraints

- Every ship knob is a per-repo setting with no floor in code; presets `cautious` and `full` are named values; `null` caps are
  unlimited **(owner)**.
- External/non-member PRs start nothing (ship, code review, CI re-runs) until a trusted member hands off (`external: member`
  default) **(owner)**.
- Code-owner review stays human; a review requirement after the App's approval is a wait, never a failure **(owner)**.
- No rules engine **(owner)**. No second PR loop, no second merge executor, no second receipt store.
- PR text (title, body, comments, check output) never reaches task text; the App never counts as a trusted trigger.
- Every write carries `{ repo, number, generation, expected_head }` and is refused on any mismatch.
- Builders: own worktree (`git worktree add <scratchpad>/wt-<name> -b <branch> origin/main`), never `git stash`, tests under
  `perl -e 'alarm shift; exec @ARGV' 600 …`, `pkill -f <worktree>/` after each run, local Codex review (`codex exec review
  --base origin/main -m gpt-6.2-sol -c model_reasoning_effort=medium -o <scratchpad>/review.md < /dev/null`) before each push,
  Conventional Commit PR titles, report a blocker after ~20 minutes without progress.

## Review Focus

- A contributor pushes while ship repairs or approves: the lease or `expected_head` refuses the write; the next round re-reads.
- A hand-back with the `ship` label still on the PR, or `handoff: all`: never re-adopted without a fresh trigger.
- A restart between filing the task and saving the adoption: the task is found by its marker, never filed twice.
- A merge-queue removal with the head unchanged and green (timeout, person dequeued): re-enqueue once on timeout; stop on a person's dequeue.
- A check red on both main and the PR with different failures in the same workflow: the PR's own failure is still fixed (signature, not workflow name).

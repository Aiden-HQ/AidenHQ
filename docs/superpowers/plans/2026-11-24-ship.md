# Ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new optional, GitHub-only `ship` module owns every PR's lifecycle, fleet-authored and handed-over alike. It takes
each PR to merge inside the repo's rules, and every knob is a per-repo setting.

**Architecture:**
- **`ship`** holds the settings, adoption records (only `hold` is stored), the round loop, the report, the metrics and the
  Fleet → Ship view. It absorbs `modules/github/service/src/pr-watch.ts` and the Maintainer watcher's `contributor_prs` pass.
- **`github`** keeps only typed effects: API commit with a fast-forward ref compare-and-swap, update-branch, approve, enqueue,
  merge, comment. `merges.ts` and `merge-gate.ts` stay the merge primitive. `decide` gains action results, and merge-gate reads
  the target branch's rules.
- **Engineers** do the judgment work, one task per PR, woken only for real work.

**Tech Stack:** TypeScript on Node 24 (`.ts` run directly), node:test, GitHub REST/GraphQL through the code host.

**Spec:** `docs/superpowers/specs/2026-11-24-ship-design.md`

## Global Constraints

- **Settings (owner):**
  - Every ship knob is a per-repo setting with no floor in code. The presets `cautious` and `full` are named values, and a
    `null` cap means unlimited.
  - `cautious` keeps today's pr-watch constants: `wakes_per_head: 3`, `ci_rounds: 3`, `same_check_heads: 2`.
- **GitHub only (owner).** codehost-local keeps its own loop.
- **Forks (owner).** Nothing runs on a fork until a member's `ship` label or `/ship` comment. That trigger adopts the fork and
  calls code review's ask path. Pushes to a fork happen only when it allows maintainer edits; otherwise the PR goes on `hold`.
- **Code-owner review stays human (owner).** A review requirement is a wait, never a failure.
- **Keep it simple (owner).**
  - No rules engine and no generator sandbox.
  - No dequeue, no stack retarget, no merge-rate limit.
  - No settings revision check.
  - At the effect, check only that the head is unchanged and the repo isn't paused.
  - The rare cases are listed in the spec's "Not handled (fails loudly)".
- **One way.**
  - No second PR loop, merge executor or receipt store.
  - `pr-watch.ts` and the Maintainer watcher's PR pass are deleted in Lane C.
- **Untrusted text.** PR text never reaches task text, and the App never counts as a trusted trigger.
- **Builders:**
  - Work in your own worktree (`git worktree add <scratchpad>/wt-<name> -b <branch> origin/main`); never `git stash`.
  - Run tests under `perl -e 'alarm shift; exec @ARGV' 600 …`, then `pkill -f <worktree>/`.
  - Before each push, run a local Codex review: `codex exec review --base origin/main -m gpt-6.2-sol -c
    model_reasoning_effort=medium -o <scratchpad>/review.md < /dev/null`.
  - Use Conventional Commit PR titles.
  - Report a blocker after ~20 minutes without progress.

## Review Focus

- **A contributor pushes while ship commits or approves.** The ref compare-and-swap or the head check refuses the write, and
  the next round re-reads.
- **A hand-back while the `ship` label is still present, or under `handoff: all`.** The PR is not re-adopted without a fresh
  trigger.
- **A crash between filing a task and saving the adoption.** The module-task `source` key returns the existing task.
- **A repo with zero required checks.** `decide` is green from the rules, and the PR merges.
- **Required checks behind a page of more than 100 contexts.** Pagination reads them all: never "can't read", never a false
  green.

  - `PRESETS: Record<"cautious"|"full", ShipSettings>`.

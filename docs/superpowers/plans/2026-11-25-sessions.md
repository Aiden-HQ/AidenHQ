# Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A long-lived opencode session is an ordinary task held by a compiled `session` agent. It runs as one deadline-free
kernel job in one standing agent computer, idles at zero tokens, is woken by kernel wake notices (comments, timers, watched
events), and merges through the code host's `github.merge`. The first slice is the case from the spec: "watch PR A; when it
merges, merge PR B".

**Architecture:** No new identity, credential, inbox or harness interface. The kernel adds a `session` job profile with four
exemptions (hard deadline, token TTL, computer pool, per-task cap), a tier rule for the `session` role and live delivery of
non-comment wakes. The launcher gains a standing-box variant that holds several leases at once and stops one session by its
process group. A new `engine-opencode` module implements `engine@1` over `opencode serve` and builds `opencode.json` from
`job.json`. A new `sessions` module holds the agent, its event watches (a module `subscribes:` reader with a committed
cursor) and later the Sessions page. The board proxies the terminal (ttyd + tmux) and opencode's web UI through the launcher,
authorised by the task creator's account.

**Tech Stack:** TypeScript on Node 24 (`node --test`), SQLite (`node:sqlite`), Docker/gVisor agent computers, opencode
1.19.6 (pinned), tmux, ttyd, the board (Vite/React + its Node server).

**Spec:** `docs/superpowers/specs/2026-11-25-sessions-design.md`. Its owner decisions 1-12 are fixed. Spike notes and configs are
in the coordinator's scratchpad, `spike/` (`opencode.json`, `drive-oc.sh`, `NOTES.md`). Copy what you need into the module.
The spike files never enter the repo as they are.

## Global Constraints

- Decisions 1-12 in the spec are fixed. A cut or change to any of them goes back to the owner, never into the build.
- One way (root `CLAUDE.md` Conventions). No fallback paths. A replaced path is deleted in the same PR, or in the follow-up its
  body names.
- `computeTier` (`kernel/src/tier.ts`) stays the only tier function. Code's hard refusals and the owner's veto still bind
  sessions. Every session write stays a kernel record.
- The owner's GitHub token never enters a box. Today a box's only credential is its `ahqj_` job token. Lane G's App
  token is the one amendment (decision 10), and the Conventions text says so in the same PR.
- Supply chain: opencode `1.19.6`, ttyd, tmux and every opencode plugin are pinned exactly, at least 7 days old. Each pin gets
  its release date in the PR body (`scripts/supply-chain/best-version.ts`, `npm-age.ts`, `pins.ts`). opencode's self-update stays
  off (`autoupdate: false`), and nothing is fetched from npm or models.dev at run time.
- Waiting is always a kernel wake (a wake notice on the task). A harness never waits in a loop or a cron of its own.
- No owner data in the product: tests use `acme/widgets`, `example.com` and documentation IP ranges.
- Generic core: the kernel knows the `session` profile and the `session` role. It never knows the agent key `session` or the
  sessions module by name.
- Minimal tests: the few end-to-end tests named in each task, and nothing else.
- Builder brief (every lane):
  - Work in your own worktree (`git -C AidenHQ worktree add <scratchpad>/wt-<lane> -b <branch> origin/main`). Assert `pwd`. Never
    `git stash`, never `git add -A`, and never touch the main checkout.
  - Run tests under a hard timeout (`perl -e 'alarm shift; exec @ARGV' 600 npm test`). Afterwards `pkill -f <worktree path>/`,
    and leave no vite or mock API running.
  - Report a blocker after about 20 minutes without progress.
  - Before each push, run a local Codex review:
    `codex exec review --base origin/main -m gpt-6.2-sol -c model_reasoning_effort=medium -o <scratchpad>/review.md < /dev/null`
    in the background. Fix the important findings, and re-run at low effort from the last reviewed sha.
  - PR titles are Conventional Commits. Builders never merge.
- Reviewer-eval-gated files (`kernel/src/tier.ts`, `writes.ts`): CI runs the eval on the PR. Don't run it by hand.

## Review Focus

1. **A session whose box was replaced by an apply.** opencode and tmux die with the box. Expected: the job ends, dispatch's
   retry starts a new job, and that job resumes the same opencode session (`spec.session`). The watch is still armed, and
   the owner hears nothing. Pinned by Task D4's restart test and Task B2's replace-on-new-image test.
2. **The same merge event delivered twice** (feed resend, service restart before the cursor commit). Expected: one wake
   notice on the task and one merge record. Pinned by Task D3 (`wakeNotice` id dedupe) and Task D4.
3. **A watch armed after the event already happened** (PR A merged before the session armed, or while the service was down,
   or older than the 3-day log). Expected: the watch fires at once from live PR state. Pinned by Task D3's reconcile tests.
4. **Sessions filling the computer pool.** Idle sessions must not take the fleet's `computers_max` slots. Expected: fleet
   jobs still admit with N sessions live; sessions are bounded by the session agent's `max_parallel` only. Pinned by Task A1.
5. **A session's timer or event arriving while the harness is mid-turn.** Expected: the wake notice is queued in
   `inbox.jsonl` and becomes the next prompt once the turn ends, never dropped and never a second concurrent turn. Pinned by
   Task C3's busy-session test.

# AidenHQ

A self-hosted platform for creating, running and managing your own AI agents and the applications they build.

Describe an agent or an app you need, and AidenHQ designs it, deploys it, runs it on a schedule or when something
happens, and keeps it maintained, on a server you control. Agents share one set of tool connections and one data
warehouse, and every write they make (a push, a deploy, a message, a config change) passes an approval gate
enforced in code. You work with all of it through **Aiden**, your chief of staff, on Telegram, Slack or the web: Aiden
turns what you ask for into work for the right agent, chases it, and brings you only the decisions.

## Building blocks

| Block | What it is |
|---|---|
| **Chief of staff (Aiden)** | The one agent you talk to. Turns chat and forwards into tasks, delegates, chases, sends the daily brief, relays your approvals word for word. |
| **Crews** | Specialist agents on schedules and events. Core: Aiden, Executive Assistant, DevOps Engineer, Agent Architect, Agent Coach, Platform Engineer. Modules add the rest (Follow-up Tracker with its Slack and inbox scouts, Meeting Librarian, Engineers, Security Watch, ...). Each is a `module.yaml` entry plus a handbook (`modules/<m>/agents/<key>/AGENTS.md`). |
| **Control plane** | [Paperclip](https://github.com/paperclipai/paperclip): tasks, routines, budgets, approvals, run history. Agents run on Codex via OpenRouter. |
| **Shared connections** | MCP servers any agent can be granted: Google Workspace, Slack, Glean, Jira, GitHub, Primer, tasks, apps (Grafana and ClickHouse are runner-only). Each optional one is a module (`modules/<m>/connections/`). Tools are tagged read or write; every call is checked against the agent's grants. |
| **Runner** | Host service for coding jobs. Pushes, PRs and merges happen only on the owner's own words, enforced in code. |
| **Apps platform** | Long-running services agents deploy and maintain (`apps-mcp`; registry is the instance's `apps.yaml` plus module apps), each sandboxed: no host access unless its registry entry grants it. |
| **Warehouse** | Shared Postgres app for sources and apps (`modules/warehouse/apps/warehouse`). |
| **Roles** | Agent roles decide which tools and restricted apps each agent may use. |
| **Catalog** | The tool catalog agents see, generated by setup from the granted connections. |
| **Self-improvement** | Corrections are captured; agents propose handbook and config changes; the Platform Engineer edits your instance repo and nothing applies until you approve. |

## Architecture

```
 You ── Telegram / Slack ──► owner channel (slack-live-mcp) ──► Aiden (chief of staff)
                                                                   │ delegates
 Board (daily view) ────────┐                                      ▼
 Paperclip UI (fleet) ──────┼───────────── Paperclip (tasks, routines, runs) ── crews (Codex on OpenRouter)
                            │                         │                          │ MCP
                            │                         │              shared connections (Google, Slack, GitHub, ...)
                            │                         ▼
                            │                 runner (host, systemd) ── coding jobs, git gates
                            └──────────────── apps-mcp ── sandboxed apps (warehouse, ...)
```

Everything runs in Docker Compose on one host, plus the runner as a systemd user unit. Inbound is LAN/Tailscale
only. See [docs/architecture.md](docs/architecture.md).

## Models and cost

Agents run on [OpenRouter](https://openrouter.ai) models, set per agent in each `module.yaml` (an instance can
override them):

| Role | Default model |
|---|---|
| Aiden and most agents | `~deepseek/deepseek-flash-latest` |
| Agent Architect, UI/UX Engineer (handbooks and design need the stronger model) | `moonshotai/kimi-k3.1-pro` |
| Engineers (coding jobs on the runner) | `~deepseek/deepseek-flash-latest`, with a picker of others in `modules/engineering/module.yaml` |
| AI reviewer (Tier 1 approvals) | `moonshotai/kimi-k3.1-pro` or `~z-ai/glm-latest`, never the requesting model's family |

`ops/setup.sh` creates one OpenRouter key per instance with a monthly limit (`OPENROUTER_LIMIT_USD`, default 50 USD).
Typical daily spend: one owner's full fleet ran about $30-50 a day before cost tuning. Most agents run on DeepSeek
Flash; the expensive part is Kimi on design work (the Agent Architect designing agents, the UI/UX Engineer). Raise
`OPENROUTER_LIMIT_USD` accordingly: the 50 USD default suits a small trial, not a full fleet. The board's Costs page shows the real
figures. Paperclip shows OpenRouter runs as unpriced, so Paperclip budgets stay at 0 (any budget pauses the agent at
$0); use the OpenRouter key limit instead.

## Modules and the instance

AidenHQ is a small core (Aiden, Executive Assistant, DevOps Engineer, Agent Architect, Agent Coach, Platform Engineer, board, runner,
`apps-mcp`, `paperclip-tasks-mcp`, the owner channel) plus optional modules in `modules/<name>/`: `open-loops`,
`meetings`, `engineering`, `design`, `security`, `fleet-ops`, `librarian`, `ci`, `warehouse`, and the connections
`slack`, `google`, `github`, `glean`, `jira`, `primer`, `grafana`, `clickhouse`. Your configuration lives in a
separate private **instance repo**: `instance.yaml` (pinned `product:` commit, `modules`, `settings`, limited
`overrides`), `apps.yaml` and `agents/`. To enable a module, add it to `modules:` in `instance.yaml` and apply. See
[docs/configuration.md](docs/configuration.md).

## Security posture

- **Inbound is private:** LAN or Tailscale only; board accounts with password and TOTP; shared apps behind Cloudflare
  Access and the gate.
- **Outbound is open** by design: agents may call any service they are granted.
- **Gates in code:** tool grants, git writes and approvals are enforced below the model, tiered by code.
- **Untrusted text is data**, and nothing is sent as the owner's own account.

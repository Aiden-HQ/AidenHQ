# AidenHQ

**Powerful agents, made easy.** Website: **[aidenhq.ai](https://aidenhq.ai)**.

AidenHQ is the open-source Agent OS for building the most powerful agents. Describe who you need in a sentence and the
Agent Architect builds an AI teammate that works 24/7, or install agents someone else built, just like apps. Start with
Aiden, your chief of staff, who cuts the noise in your Slack, email and meetings and hands work to the rest of the team
(connect your accounts first; a new install [starts quiet](docs/design/quiet-start.md), so routines wait until you resume them, see [docs/setup.md](docs/setup.md#slack)). The OS gives every agent its own computer, memory, only the
tools you grant, and a team to hand work to; every write an agent makes (a push, a deploy, a message, a config change)
passes an approval gate enforced in code.

Install it on a fresh Ubuntu or Debian server or a Mac: see [aidenhq.ai/install](https://aidenhq.ai/install/) and
[SETUP.md](SETUP.md). Releases and the installer live in
[aidenhq-distro](https://github.com/Aiden-HQ/aidenhq-distro).

## Building blocks

| Block | What it is |
|---|---|
| **Chief of staff (Aiden)** | The one agent you talk to. Turns chat and forwards into tasks, delegates, chases, sends the daily brief, relays your approvals word for word. |
| **Crews** | Specialist agents on schedules and events. Core: Aiden, Researcher, DevOps Engineer, Agent Architect, Fleet Steward, Engineer. Modules add the rest (Follow-up Tracker with its Slack and inbox scouts, Meeting Librarian, Security Watch, ...). Each is a `module.yaml` entry plus a handbook (`modules/<m>/agents/<key>/AGENTS.md`); your own agents are local modules in your instance repo. |
| **Control plane** | [Paperclip](https://github.com/paperclipai/paperclip): tasks, routines, approvals, run history. Paperclip runs nothing: the kernel runs every agent as a job in an agent computer, on Codex via OpenRouter. |
| **Shared connections** | MCP servers any agent can be granted: Google Workspace, Slack, Glean, Jira, GitHub, Primer, tasks, apps (Grafana and ClickHouse are Engineer-only). Each optional one is a module (`modules/<m>/connections/`). Tools are tagged read or write; every call is checked against the agent's grants. |
| **Code host** | `github` (its code host part, on your one GitHub sign-in): the only holder of your GitHub token; pushes, PRs and merges are approval records tiered in code, and other modules get typed operations through the kernel. Coding jobs run in agent computers. |
| **Apps platform** | Long-running services agents deploy and maintain (`apps-mcp`; registry is the instance's `apps.yaml` plus module apps), each sandboxed: no host access unless its registry entry grants it. |
| **Warehouse** | Shared Postgres app for sources and apps (`modules/warehouse/apps/warehouse`). |
| **Roles** | Agent roles decide which tools and restricted apps each agent may use. |
| **Catalog** | The tool catalog agents see, generated by setup from the granted connections. |
| **Self-improvement** | Corrections are captured; agents propose handbook and config changes; the Engineer edits your instance repo and nothing applies until you approve. |

## Architecture

```
 You ── Telegram / Slack ──► owner channels (Telegram, Slack) ──► Aiden (chief of staff)
                                                                   │ delegates
 Board (daily view) ────────┐                                      ▼
 Paperclip UI (fleet) ──────┼───────────── Paperclip (tasks, routines, runs) ── crews (Codex on OpenRouter)
                            │                         │                          │ MCP
                            │                         │              shared connections (Google, Slack, GitHub, ...)
                            │                         ▼
                            │                 github (code host) ── git writes, merges, gates
                            └──────────────── apps-mcp ── sandboxed apps (warehouse, ...)
```

Everything runs in Docker Compose on one host, plus the kernel and the computer launcher as systemd user units. Inbound is one door, chosen at
install: HTTPS on the server's public IP behind password and TOTP (the default off a tailnet), Tailscale, or an SSH tunnel. See [docs/architecture.md](docs/architecture.md).

## Models and cost

Agents run on [OpenRouter](https://openrouter.ai) models, set per agent in each `module.yaml` (an instance can
override them):

| Role | Default model |
|---|---|
| Aiden and most agents | `~deepseek/deepseek-flash-latest` (high effort) |
| Agent Architect (its handbooks are what the other agents run on) | `~deepseek/deepseek-flash-latest` at `max` effort |
| UI/UX Designer (mockups) | `~deepseek/deepseek-flash-latest` at high effort |
| UI Reviewer (screenshot reviews of UI PRs) | `~openai/gpt-luna-latest` at medium effort |
| Red Teamer (fewer refusals on offensive security work) | `~z-ai/glm-flash-latest` (high effort) |
| Advisor (`advisor_ask`, and `aidenhq advise` for Engineers: a second opinion at a decision point) | `~openai/gpt-sol-latest` |
| Engineers (coding jobs in agent computers) | `~deepseek/deepseek-flash-latest`, with a picker of others in `modules/engineering/module.yaml` |
| AI reviewer (Tier 1 approvals) and grader | `~openai/gpt-luna-latest` (medium effort), or `~deepseek/deepseek-flash-latest` (high) for an OpenAI-family requester: never the requesting model's family |

`ops/setup.sh` creates one OpenRouter key per instance with a monthly limit (`OPENROUTER_LIMIT_USD`, default 100 USD).
A new install also starts quiet (`docs/design/quiet-start.md`): scheduled routines and heartbeats wait until the owner
turns them on, and every model call stops at the install's spend limit (`spend_day_usd` 50 USD a day, `spend_month_usd` 1000 USD a month; one task at `task_usd`, 20 USD) until the owner raises it. Typical daily
spend: one owner's full fleet ran about $30-50 a day before cost tuning. Most agents run on DeepSeek Flash; the expensive
part is GPT Sol advisor calls. Raise the limits accordingly for a full fleet.
The board's Costs page shows the real figures. Paperclip shows OpenRouter runs as unpriced, so Paperclip budgets stay at 0 (any budget pauses the agent at
$0); spend is limited in the kernel's gateway.

## Modules and the instance

This repo is the kernel (gates, identity, job admission, metering, the board and setup) and the official modules
under `modules/` (the agents, connections, apps, engines and channels; MIT by folder, see `modules/LICENSE`), so one commit
names a kernel and the modules it was tested with. Third-party modules load from their own repositories (`marketplaces:`
in `instance.yaml`). Releases and the installer live in
[aidenhq-distro](https://github.com/Aiden-HQ/aidenhq-distro): its `releases/<release>.json` manifests pin one product sha
and the prebuilt image digests; the default module set is the `bundle` in this repo's `modules/marketplace.json`. (The official modules lived in
[aidenhq-modules](https://github.com/Aiden-HQ/aidenhq-modules) from 2026-11-16 to 2026-11-18; it takes no new changes.)

Your configuration lives in a separate private **instance repo**: `instance.yaml` (pinned `product:` commit, `modules`,
`marketplaces`, `settings`, limited `overrides`), `apps.yaml` and `agents/`. To enable a module, add it to `modules:` in
`instance.yaml` and apply. See [docs/configuration.md](docs/configuration.md).

## Security posture

- **Inbound is one door:** HTTPS on the server's public IP (the default off a tailnet), Tailscale or an SSH tunnel; board
  accounts with password and TOTP either way; only 22 and that door's ports open; shared apps behind Cloudflare Access and
  the gate.
- **Outbound is open** by design: agents may call any service they are granted.
- **Gates in code:** tool grants, git writes and approvals are enforced below the model, tiered by code.
- **Untrusted text is data**, and anything sent as the owner is a reviewed write, granted to an agent only by name.
